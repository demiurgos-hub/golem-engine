# Changelog

All notable user-facing changes to Golem Engine are documented here.

This project follows the changelog categories from Keep a Changelog: Added, Changed, Deprecated, Removed, Fixed, and Security.

## Unreleased

### Added

- The independent `golem/geometry` module reads and writes bounded, hash-verified binary source sidecars. Canonical meshes retain float32/float64 precision; compact terrain keeps normalized float32 heights and surface bits, with explicit physical/navigation triangulation during cooking.
- Physics and navigation source loaders accept compact Scribe v2 sidecars through `DecodeFile` or `DecodeWithGeometry`, while keeping v1 inline inputs readable. Physics applies per-placement affine transforms and reflection before exact zero-area normalization; prepared sources retain self-contained canonical geometry and deterministic fingerprints.
- Scribe selected-world exports now write small v2 descriptors plus transactional binary sidecars: one canonical mesh per authored asset, affine placement matrices, and compact terrain samples/holes. Optional stable identity resolvers support consumer-assembled saved worlds; export results expose all committed dependency paths/hashes. Existing source ownership, no-op export and rollback protections cover binary artifacts too.

- A bounded `examples/unity-integration` consumer connects selected Scribe definitions, generated Go/C# state, definition-based Unity prefabs, server physics/navigation and paired checkpoint recovery over a real WebSocket. Its runner reuses the saved content fixture project, stages current sources and records each run separately; scene/placement export and published dependency resolution remain separate work.

- Scribe content export sets capture explicitly selected prefab and ScriptableObject definitions through consumer adapters, including resolved variants, nested records, enums/flags, defaults, stable IDs and checked references. Export and validation reuse Scribe ownership and rollback; existing entity and catalog exports remain compatible.
- Optional `content` configuration generates immutable typed Go definition access and a finalized versioned bundle. Content stays separate from world replication, with strict validation, explicit pinned imports and independent schema/content hashes.
- Definition-aware Unity presentation selects different prefabs for one generated entity type using an explicit definition-ID selector and validated registry.
- `CreateEntityWithSetup` delays entity publication until setup succeeds and rolls back failed attachments without spawn/remove effects. `LoadSnapshotStrict` adds startup-only checked, hook-free entity restoration; content-pinned snapshot helpers preserve saved mutable state and reject mismatched content before restoration.

- Snapshot decoding rejects truncated, overflowing and trailing data before restoration while preserving the existing binary format.

- Continuous physics resolves coupled fast impacts through bounded native contact and joint continuation, including thin objects pushed against walls and motor-driven collisions. It retains the original force/gravity duration and drive budgets, reports owned intermediate poses, and faults the interacting frame if required work cannot complete.

- Physics qualification provides source-matched focused, engine integration, Windows capacity and Linux save/restore evidence, with a combined report that preserves failed and missing gates. The runner can select upstream's native release build while retaining explicit Golem validation. Extended matrices and the soak are excluded from the selected delivery; full-size Windows counts and the 50 ms p99 threshold remain required.

- Physics frame metrics, stress results and debug captures expose separate local TOI continuation work counts, including failed attempts. Participant and contact-row totals describe work performed; native solver call counts remain independent of the number of observed path samples.

- Physics qualification includes actual Unity 6 simulation comparisons for forces, impulses, torque, falling, bouncing, stacks, physical pushing and hinge constraints. Captures retain the initial exported source and commands; simulation tolerances remain separate from query accuracy and full workload gates.

- Resolved-content qualification captures copied server prefab catalogs, activation recipes and database pose variants in bounded Unity batches, preserving source identities, variant removals and complete physical signatures. Loader checks retain inactive geometry and compare native queries by collider identity; missing content and unsupported geometry remain explicit failures.

- Physics cooking preserves small nonzero triangles and unreduced convex geometry with up to 256 hull vertices, 512 faces and 768 edges. Version-2 cooked artifacts and the widened native hull format require recooking; old native snapshots are rejected. Unity source normalization removes only exactly zero-area faces, retaining original triangle ordinals and a hash of the original geometry in metadata. Full geometry/workload qualification remains separate.

- Physics qualification can exercise repeated coordinated geometry activation/replacement/unloading and save complete paired checkpoints for fresh-process recovery, including projectile and route-direction state. Latency results retain the complete final frame when it exceeds the requested measurement duration; elapsed time alone does not qualify a churn/restart soak.

- Live physics bodies can atomically switch movement mode and controller configuration with explicit velocity retention or clearing, preserving body/collider/joint handles and entity attachment. Server policy changes invalidate old trajectory tokens; callback requests can be queued for the next tick. Accepted contact continuity uses actual geometry and swept intervals without synthetic forces.

### Changed

- The unreleased Box3D adapter now uses fixed native stepping: four steps per 20 Hz frame by default, with `SolverVelocityIterations` and `SolverRelaxIterations` both defaulting to 1. Retained navigation/controller/support boundaries share the same elapsed time. The experimental global adaptive-refinement settings and penetration ceiling are removed; captured navigation safety still rejects an unsafe interacting frame as a whole, and query/placement precision is unchanged. World `Config.Continuous` controls CCD; per-body `Continuous` selects the native bullet policy separately.

- Breaking change to unreleased physics captures: portable physics checkpoints and Go/Unity debug captures now use version 2 with native solver settings. Version-1 physics checkpoints require explicit state migration; old debug captures must be regenerated. The paired root checkpoint envelope, entity snapshots and portable Scribe source keep their existing versions. Readers reject obsolete physical payloads explicitly instead of ignoring retired configuration fields.

- Motion queries reuse private traversal scratch while preserving geometry coverage and independently owned event records. Focused allocation checks cover query and contact capture paths; full workload capacity still requires qualification.

- Navigation qualification's `Suite` and `Full` launchers now run the three mixed scene families at 1,000 agents only; `Full` retains the two-hour 1,000-agent soak. Existing diagnostic agent-count controls remain available.

### Fixed

- Precise sweeps clip subsequent searches after a nearer hit while preserving equal-distance identities and unchanged geometric accuracy. Rounded mesh contacts use bounded scratch sized to their actual maximum output without dropping triangles or contact points.

- Small physics edits synchronize active and changed static bodies without refreshing every untouched static collider. Portable handle lookups retain world, generation and type validation while avoiding repeated hash-table searches during simulation.

- Physics avoids building continuous-collision scratch for intervals with no eligible motion, reuses generation-validated collider lookups, and reduces allocations while retaining every observed path sample. Qualification timing separates scene setup and explicit route admissions from automatic replans; full-load geometry edits preserve the active routes' quarantine boundaries.

- Physics contact exit and cleanup events report zero force instead of repeating the previous impact. Owned native observations retain the correct body pose and contact witness through rebounds, with solver-response impulses counted once and kept separate from sensor overlap.

- Unity physics export reads imported mesh geometry even when runtime Read/Write is disabled, without changing importer settings. Submesh indices, source identity and geometry validation remain preserved.

- Relative-motion queries and continuous contact intervals resolve exact rotational endpoint tangencies without loosening geometric tolerance. Bounded interval certificates preserve separation and reentry when conservative advancement stalls.

- Physics advances the configured native intervals without the former global refinement stalls. Native TOI/contact response regressions cover fast crossings and thin-wall impacts while retaining momentum transfer, bounded drives and the captured navigation safety checks. Focused correctness results do not establish full workload or platform qualification.

- Geometric sphere/capsule queries preserve exact touching on flat triangle faces, avoiding spurious rejection by zero-penetration spawn admission. Touching pair results retain their feature identity and witnesses. The correction keeps float32 geometry and does not relax penetration thresholds.

- Physics contact transitions remain private until the whole frame is accepted. Shutdown emits terminal cleanup for accepted pairs only and rejects callback commands. Constraint-force reads reject pending or faulted frames. Upright joints use the authored Y-up axis and consistent warm starting through repeated yaw rotations.

- Physics stress scene manifests record the selected solver configuration, including worker count, instead of displaying defaults alongside a tuned run.

- Physics attachment and teleport validate complete solid geometry before changing ownership or poses; geometric penetration requires an explicit placement policy. Rejected motion admission preserves actual displacement and support from the shared solver while discarding proposed navigation and traversal progress.

- Capacity qualification checks complete route segments against the physical cylinder and source obstacles before timing. Its fixture records separate body and bake dimensions and an explicit conservative bake margin, retaining unchanged body sizes and motor behavior; old unsafe fixtures fail preflight with the offending segment and clearance.
- Terrain qualification uses a tighter contour simplification setting after physical clearance checks identified two wall-clipping routes. Geometry, destinations and physical body dimensions remain unchanged; narrow-gap presence is not claimed as differentiated profile coverage.

- Navmesh routes preserve the selected ground surface height at their true start and end. Agents on detailed ramps no longer stall against a vertically offset first corner; authored traversal anchors and truncated route endpoints keep their existing meaning.

- Surface navigation quarantines authored-link metadata edits even when attached endpoints lie outside the source height bounds within climb tolerance. Old routes cannot transfer unchanged across those edits.

- `NavAgent.SetDestination` clears the old path and velocity when a replacement cannot be found, including a missing backend or nil server. A failed destination no longer leaves an NPC moving toward its previous goal.

- Go engine and collision/navigation backend modules now pin the committed shared-helper revisions, so standalone builds resolve those helpers without a local workspace.

- Unity Scribe replaces generated files atomically and restores original file bytes after handled export failures. If restoration fails, errors identify every affected path and explicitly report incomplete rollback. Configuration, manifest, and artifact read failures include their input path instead of being mistaken for missing output or escaping without context. Handwritten files introduced during an export are rechecked before replacement or deletion.

- Unity spawns initialize each transform binding once for its current entity, preserving view callback counts and serialized child targets. **Behavior change:** repeated same-entity binds during spawn callbacks no longer force another snap. Set the transform explicitly in a callback or rebind after spawn dispatch returns if another snap is intentional. Explicit binds outside spawning still snap, including same-entity binds; existing generated views do not need regeneration.

- An explicit JavaScript WebTransport ACK interval of `0` now uses the same 1 ms coalescing default as omission. Positive intervals and first-pending-ACK deadlines are unchanged.

- JavaScript bake cleanup requires a Golem generated header before deleting recognized intermediate TypeScript files. Authored files with generated-looking names, declarations, and symlinks are preserved; normal generation still overwrites its selected outputs.

- Session avatars remove their registered 2D and 3D colliders before `OnRemove` during disconnect cleanup and failed-spawn rollback, preventing leftover collision shapes.
- Native Go clients wait for the first reliable ordered WebTransport datagram before delivering later messages. An unresolved ordered gap lasting more than three seconds reports a disconnect even when no further datagrams arrive.
- WebTransport servers coalesce acknowledgements from the first pending packet, so continuous command traffic cannot postpone ACKs indefinitely.
- Go server datagram sequence comparison treats a separation of exactly 32768 as ambiguous, matching the Go client and preventing false receive-window advances or loss reports.
- Removing a session clears all of its traffic-counter history, including inbound packet and ACK counters used in replication diagnostics.
- JavaScript generation emits a valid `never` synchronized-entity union for schemas without entities, including world-only and event-only clients.
- Go and JavaScript WebTransport clients acknowledge sustained incoming state traffic within their configured coalescing interval. Continuous updates no longer postpone acknowledgements indefinitely and disconnect idle clients when the interval matches the server tick rate.
- JavaScript WebTransport clients retain queued commands that have not been sent when an acknowledgement for an earlier packet arrives, preventing missing ordered commands and subsequent disconnections.

## [0.3.0] - 2026-08-24

### Added

- WebTransport-first connection plans now support a sequential WebSocket fallback across the JavaScript, Phaser, native Go, Ebiten, and Unity clients. Capability checks run before lazy per-candidate credential resolution, WebTransport establishment is bounded to five seconds, failed candidates are fully closed, and an opened WebSocket remains preferred for reconnects until the credential-free endpoint configuration changes. Existing direct `Connect`/`connect` APIs and primary-only bootstrap helpers remain compatible.
- Public fallback APIs include JS/TS `RealtimeEndpoint` / `ConnectPlan` / `ConnectInput`, Go `RealtimeEndpoint` / `ConnectionPlan` / `GameClient.ConnectPlan`, Ebiten plan providers, and Unity `GolemRealtimeEndpoint` / `GolemConnectOptionsResolver` plus the cancellation-aware config overload. Built-in Unity WebTransport fallback capability is Windows x64 without certificate hashes; built-in WebSocket remains unavailable on WebGL.
- One Golem server can expose its configured primary handler plus `Server.WebSocketHandler` / `Listener.WebSocketHandler`, sharing session IDs, hooks, snapshots, visibility, statistics, tick state, and shutdown. `RealtimeConfigOptions.WebSocketFallbackURL` advertises the optional nested WebSocket endpoint with `Cache-Control: no-store`; automatic datagram-lane replication uses WebTransport datagrams per session and sends equivalent wrapped stream updates to WebSocket sessions, while explicit mixed datagram broadcasts skip sessions without datagram support.
- Command payload fields can now use all-or-nothing `{ tag: N, type: T }` definitions to preserve direct protobuf field numbers when appending fields; untagged commands keep legacy alphabetical numbering, and entity-targeted commands reserve tag 1 for `entity_id`.
- Event payload fields may opt into explicit direct protobuf tags with `{ tag: N, type: T }`. Tagged events require every payload field to carry a unique legal tag, preserving existing wire numbers when additive fields would otherwise reorder legacy alphabetical numbering. Re-run `golem-bake`; entity-targeted event tag 1 remains reserved for `entity_id`.
- Entity, command, and event schema files accept an optional root `tag` that pins their generated `EntityUpdate`, `ClientMessage`, or `ServerEvent` oneof field. Untagged declarations retain legacy sequential assignment, `EntityRemoved` remains directly after untagged entity state/delta pairs, and bake rejects invalid, reserved, overflowing, duplicate, or overlapping explicit tags. Re-run `golem-bake` after opting into pinned envelope tags.
- `Session.IsClosing()` exposes the monotonic, concurrency-safe close-request state immediately, allowing delayed hydration or other asynchronous work to avoid attaching gameplay state before `OnDisconnect` runs.
- `Session.RequestCloseWithReason(reason)` atomically marks a session closing, drops later traffic, and signals its write pump before returning, while the clean WebSocket/WebTransport close handshake runs asynchronously with the retained reason. Concurrent/repeated close calls are idempotent and the first close reason wins, so tick and HTTP callbacks can revoke a session without waiting on transport I/O. `CloseWithReason` remains the blocking-handshake API.
- `golem-phaser` connection-option callbacks may return a `Promise`, allowing each initial connection and reconnect to fetch fresh short-lived authentication or transport configuration. Pending results are ignored after disconnect, plugin destruction, or a newer connection attempt.
- Optional `protocol_constants` catalog support in `golem.yaml`: define validated shared string sets once and `golem-bake` emits matching Go constants in `entities_pb.go`, TypeScript `as const` objects and union types in `entities_pb`, and C# static string classes in `EntitiesPb.cs`. Catalog names use canonical snake_case; sets reject empty members, generated-name collisions, blank or whitespace-padded values, and duplicate values. These constants do not add protobuf fields or change snapshot fingerprints. Re-run `golem-bake` after catalog changes.
- World schema files accept an optional root `tag` to pin their `WorldUpdate` oneof field number. If any world schema sets a tag, every world schema must set a unique value of at least 1; otherwise tags remain auto-assigned by sorted world type name. Pin tags before adding more world types when existing clients must keep wire-compatible numbers, then re-run `golem-bake`.
- `Session.CloseWithReason(reason)` for short transport close reasons (WebSocket close reason / WebTransport error message).
- Generated `EntityManager.clear()` / `Clear()` removes all known entities, fires remove listeners, and resets revision tracking. Re-run `golem-bake`.
- Bounded background tasks via `Server.SubmitTask` (Pond-backed worker pool) plus tick-safe `Server.Post`. Work runs off the tick goroutine; completions and posts drain after `OnTickStart` and before session-message drain under one `AsyncCallbacksPerTick` budget (default 256; round-robin starts completion-first on the first drain and persists preference across ticks so budget `1` cannot starve `Post` under sustained completions). Defaults: `TaskWorkers` 4, `TaskQueueCapacity` 256, `TaskCompletionQueueCapacity` 256, `PostQueueCapacity` 1024 (zero selects defaults; negatives panic in `NewServer`). Full task/post queues return `ErrTaskQueueFull` / `ErrPostQueueFull` without blocking; a full completion queue applies worker backpressure until capacity frees or shutdown. Caller and run contexts are merged for work; panics are recovered into an error wrapping `ErrTaskPanicked` and still produce a tick completion while running. `Run` is single-use (`ErrServerAlreadyRun`). `Post` / `SubmitTask` return `ErrServerNotRunning` before `Run`, during shutdown, and after `Run` returns; shutdown stops acceptance, cancels workers, waits for the pool, and discards queued callbacks so none run after the loop exits. Workers must not touch tick-owned server state — only completion/`Post` callbacks may. `Server.TaskStats()` exposes accept/reject, work-finished vs callback-executed, cancellation, panic, Post counters, and approximate live queue/worker gauges (`QueuedTasks`/`RunningTasks`/`QueuedCompletions`/`QueuedPosts`).
- Owner-only entity vars (`visibility: owner` in entity YAML): empty/`all` remain public; other values are rejected at bake time. Generated Go server entities with owner-only vars implement `OwnerScopedEntity` (`PublicFullUpdate`, `PublicReplicationMask`) while keeping authoritative `FullState`/`FullUpdate` for persistence and owner delivery. Non-owners receive redacted full state and public-masked deltas (zero public mask sends nothing) on connect snapshots, spawn/full, stream deltas, and compact eventual datagrams (with oversized/stream fallback); cache keys separate public vs private payloads. `SetOwner` still changes command authority immediately and, for owner-scoped entities, queues a coalesced replication refresh on the next pass (old known owner gets public full; final new known owner gets authoritative full; same-tick A→…→A is a no-op; `SetOwner(..., 0)` clears ownership). `visibility: owner` is replication redaction only — command authorization remains the separate `Owner` check. Client decode APIs are unchanged. Re-run `golem-bake`.
- Per-session world-value delivery and connect-snapshot exclusion: `Server.SendWorldData(sessionID, data)` serializes a supplied world value (without mutating `Server.World`) and sends it on the reliable stream to one session, so two clients can receive different maps that share the same `WorldName`. `Server.SendStoredWorldData(sessionID, name)` is the store-backed convenience matching `PushWorldData` (missing names remain a nil no-op). `ServerConfig.WorldSnapshotExclude` omits listed names from the connect snapshot while keeping them in `Server.World`; callers own on-demand delivery. Reliable frames are capped at 256 KiB — prefer `map_url` for large maps.
- Named visibility groups gate entity replication in interest and broadcast modes: `Server.JoinVisibilityGroup` / `LeaveVisibilityGroup` / `SetEntityVisibilityGroup` (empty group = public). Grouped entities require membership (and FOI in interest mode); grouped globals bypass distance but still require membership. `SessionsKnowing` reflects actual replication known state, not raw membership. Broadcast mode maintains per-session known sets (connect snapshot seeds after successful delivery; blind `BroadcastBatch` remains a fast path when safe). Visibility policy is point-in-time: APIs never wait on network I/O, and a mutation after a replication/snapshot decision takes effect on the next pass via known-set enter/exit (already selected/queued frames are not retroactively revoked).
- Cross-client realtime bootstrap helpers consume JSON from `Server.RealtimeConfigHandler` (`transport`, `url`, optional hex `serverCertificateHashes`, optional `eventualAckIntervalMs`): JS `fetchRealtimeConfig` / `connectOptionsFromRealtimeConfig` / `withQueryParam` / `withQuery` (optional `signal` overrides `init.signal`; Phaser prefetch/cache into synchronous `connectionOptions`); Unity `GolemRealtimeBootstrap` / `GolemConnectOptions` / `GameClient.Connect(GolemConnectOptions)`; Go `golem-go-client` remains the native reference. Fetch validates transport/url; `eventualAckIntervalMs` absent/zero keeps transport defaults, while negatives, fractions, non-finite values, and values outside signed int32 are rejected. Query helpers preserve existing params (Unity append-only, no UriBuilder rebuild), append encoded values (duplicates allowed), deep-copy hash bytes, and propagate ACK intervals. JS/Unity bound response reads in-stream (error ≤512 B, config ≤64 KiB). Go sanitizes `*url.Error` so endpoint query/fragment tokens are not leaked.
- Unity generated `ClientFactory` is options-aware (`Func<GolemConnectOptions, IGolemTransport>`). `CreateClient(Func<IGolemTransport>)` / parameterless `GameClient` factories are obsolete: `Connect(string)` still works, but `Connect(GolemConnectOptions)` with a non-empty transport fails clearly instead of ignoring selection. Built-in `GolemWebTransportTransport.FromConnectOptions` rejects unsupported browser-style certificate hashes; custom options-aware factories own certificate policy (e.g. `AllowUntrustedCertificates`). Re-run `golem-bake` for C# clients.
- `golem/auth` provides `UpgradeHandler` / `UpgradeOptions` for token-in-query-param authorization on `Server.OnUpgrade` (default param `token`). Games supply `Validate`; missing/blank tokens are rejected without calling it, validator data becomes `Session.Data`, and validator errors keep `errors.Is`. This is not an account/JWT framework. Pair with client `WithQueryParam` / realtime bootstrap helpers.
- Generated Go server `Runtime.LoadSnapshotIfExists` loads a schema-checked snapshot when the file is present (`false, nil` if missing) and preserves `snapshot.ErrFingerprintMismatch` for `errors.Is`. `Runtime.RunSnapshotAutosave` is a blocking, caller-owned loop that validates a positive interval, serializes each asynchronous `SaveSnapshot`, returns save errors, and exits with `ctx.Err()` on cancel after awaiting any in-flight save — if that in-flight save fails, the save error is returned instead of `ctx.Err()`. Re-run `golem-bake`.
- Generic `OverlapOfType[T](s, entityIDs)` resolves overlap (or any) entity ID lists through `Server.Get`, keeps entries that satisfy `T` in input order, skips missing IDs, and returns nil for empty input or no matches. Compose with `OverlapCircle` / `OverlapBox` / `OverlapSphere` / `OverlapBox3D` (for example `OverlapOfType[*Mob](s, s.OverlapCircle(...))`). A nil `*Server` always panics with `golem: OverlapOfType: Server must be non-nil` (including empty ID lists).
- Schema-declared colliders and named collision matrices: optional entity `collider` (`aabb`/`circle` in 2D, `aabb3d`/`sphere` in 3D, plus `layer` and optional `trigger`) and optional top-level `collision` in `golem.yaml` (`layers` ≤ 32, symmetric `collides` pairs including self-pairs like `[Player, Player]`; duplicate unordered pairs rejected). Generated Go server `Synced*` types emit `Collider()` or `Collider3D()`; generated `Runtime` exposes `Layers`+`EnableCollision` or `Layers3D`+`EnableCollision3D` (nil backend panics before installing helpers). `CreateEntity` / snapshot restore register matching providers after successful insertion and before `OnSpawn`; `DeleteEntity` removes shapes before `OnRemove`. Call `EnableCollision` / `EnableCollision3D` before spawning or loading snapshots of collidable entities. 2D/3D parity here is named layers plus automatic lifecycle — not per-entity contact-event dispatch (still 2D-only, pre-existing). Collider metadata is bake/runtime only and does not change the schema fingerprint or wire format. Re-run `golem-bake`.
- `CollisionLayers3D` / `NewCollisionLayers3D` provide the 3D named-layer equivalent of `CollisionLayers` (`Bind`, `Define`, `SetCollides`, `Add`, `Set`, `Remove`, `Layer`, `Mask`, `MaskFor`) around `collision3d.Backend`.
- `Server.SpawnAvatar`, `Server.Avatar`, and generic `AvatarOf[T]` bind a session to its player entity with optional FOI (`AvatarOptions`), concurrency-safe session↔entity indexes, and automatic disconnect cleanup (`RemoveFOI`, reap any still-bound avatar — including replacements spawned in `OnDisconnect`) after the user hook. Duplicate `SpawnAvatar` for a live avatar is rejected; negative `FOIRadius` is rejected; `DeleteEntity` clears avatar indexes in O(1). `SetOwner` transfers command authority only — not avatar identity. Server FOI APIs (`AssignFOI`, `RemoveFOI`, `SessionsKnowing`, interest tick grid/diff) are mutex-guarded for concurrent use.
- Generated Go server `Synced*` entities expose `BindServer` / `Server()` so gameplay code can reach the owning `*golem.Server` without package-level globals. `CreateEntity` binds before registry insertion (and thus before `OnSpawn`); `Server()` is nil until then. Re-run `golem-bake`.

### Changed

- **Breaking:** JavaScript, Go, and Unity clients use two command sends: `send`/`Send` and `sendOrdered`/`SendOrdered`. On WebTransport, the first uses reliable unordered datagrams and the second uses reliable ordered datagrams; on WebSocket, both use the reliable stream. WebTransport commands must fit the lane payload budget (1176 bytes unordered or 1174 bytes ordered) and do not fall back to the stream when oversized. Generated per-command helpers are now `send{Name}`/`Send{Name}` and `send{Name}Ordered`/`Send{Name}Ordered`; re-run `golem-bake`.
- JS `ConnectOptions` now includes optional `eventualAckIntervalMs` (already consumed by the WebTransport channel at runtime).
- **Breaking:** `golem-phaser` now targets Phaser 4 and requires `phaser >=4.0.0`. Phaser 3 projects must upgrade their Phaser dependency before using the package.
- **Breaking:** Phaser clients now register `GolemPlugin` globally with the `golem` scene mapping instead of extending `GameScene`; the connection persists across scene transitions.
- **Breaking:** The `phaser` codegen integration now emits one `GolemPhaser.ts` registry module instead of per-entity `*Bridge.ts` subclasses. Re-run `golem-bake` and remove old bridge files from consumer projects.
- **Breaking:** Phaser entity presentation now uses generated `defineEntityViews` registries and scene mounts instead of `createSpriteView`, `createGpuEntityView`, and generated-manager constructor registration.
- **Breaking:** Generated JavaScript listener registration methods now add listeners rather than replacing a single callback and return an unsubscribe function.
- Entity lifecycle hooks and custom generated-manager subclasses remain available for advanced model logic, but Phaser presentation is kept separate from synchronized entities.

### Removed

- `GameScene`, `createSpriteView`, `createGpuEntityView`, Phaser bridge interfaces, and generated Phaser `*Bridge.ts` files.

### Fixed

- Unity EditMode callers no longer trigger an invalid `DontDestroyOnLoad` call when the main-thread dispatcher is first created outside Play Mode.
- Native Go connection plans now reconnect WebSocket-only configurations without treating them as fallback affinity, reject relative, hostless, userinfo-bearing, or transport-incompatible endpoint URLs before resolving credentials or dialing, and safely advance past built-in WebTransport dial errors without a typed-nil close panic or intermediate failure logs. Realtime bootstrap HTTP errors now report only the status code instead of exposing an untrusted response body.
- The native Go WebSocket client now raises the underlying library read limit to Golem's 256 KiB reliable-message cap, so valid world and entity snapshots larger than 32 KiB are not disconnected during setup.
- Ebiten lifecycle connects no longer overwrite a reconnect scheduled by a disconnect callback that arrives during the physical connection attempt, and credential-bearing connection-plan/options provider errors are now opaque in returns and logs while preserving their wrapped cause.
- Caller-mounted WebSocket fallback sessions now clear inherited HTTP server read/write deadlines before upgrade, so ordinary request timeouts cannot terminate long-lived realtime connections. Listener shutdown fences new admission, tracks handlers from authorization through physical acceptance and snapshot delivery, waits for their cleanup without racing a late handler registration, and also runs when `Server.Run` receives an already-cancelled context.
- Mixed-transport replication statistics now count reliable-stream fallbacks from eventual state and use each session's immutable physical transport and actual chunking. Targeted empty datagram batches reject WebSocket sessions consistently, and WebTransport certificate hashes are deep-copied at the public boundary.
- Reliable stream frames now support bounded payloads up to 256 KiB across the Go server and JavaScript, native Go, and Unity clients. Transport writes remain chunked where applicable, while larger world snapshots no longer fail session setup at the former 32000-byte logical-message limit.
- Native Go WebSocket/WebTransport dial, send, read, write, and close errors now redact credential-bearing URLs before logs, returns, `lastErr`, and disconnect callbacks. Structured `*url.Error` causes retain `errors.Is` / `errors.As`, generic ticket-bearing errors use a credential-free public message, and malformed URLs render as `<invalid-url>`.
- Built-in JavaScript WebSocket/WebTransport channels no longer log or forward raw browser `ErrorEvent` / runtime `Error` strings, which may repeat credential-bearing connection URLs. Runtime failures delivered through `DisconnectInfo.error` are credential-free, and invalid URLs are logged as `<invalid-url>`.
- Slow-session queue overflow and generated Go server rejection of malformed commands now initiate the clean transport close handshake asynchronously, so tick-time replication and command dispatch do not wait on a slow peer. Re-run `golem-bake` to update generated Go server helpers.
- JS `PbReader.int32()` now correctly decodes negative protobuf int32 varints (10-byte sign-extended form). The previous float-based `_uvarint` path lost precision and commonly returned `0`, which broke signed fields such as battle `visual_hp_change` damage deltas on the client.
- Intentional `Session.Close` / `CloseWithReason` now performs a WebSocket close handshake (`StatusNormalClosure`) instead of `CloseNow`, and WebTransport closes with the optional reason string. JS clients therefore observe `wasClean` and do not auto-reconnect after a server kick (e.g. latest-session-wins character takeover).
- `GameClient` (JS and Go) clears the entity manager on disconnect when `clear`/`Clear` is available, so stale entities cannot linger after a transport drop that lost remove frames.
- Entities that leave and re-enter a field of interest or visibility group now respawn even when their state revision did not change while hidden. Interest-only removals retain the live revision; hard deletions still use a newer tombstone revision to reject late state.
- `Server.SubmitTask` accounting now increments `TasksAccepted` before Pond can run user work: a per-submission start gate opens only after a successful `TrySubmitErr` and the accepted increment (rejected full-queue submissions are not counted and never open the gate). This keeps `TasksFinished` / `TasksCancelled` / `TaskPanics` from racing ahead of `TasksAccepted` when a worker claims a task immediately, without blocking the tick on queue capacity.
- `Server.Run` with an already-cancelled caller context now linearizes shutdown synchronously before the tick loop or `Post`/`SubmitTask` acceptance, while keeping the independent internal run context for Pond shutdown ordering.
- `golem-go-client` `GameClient.Disconnect` (and therefore `Connect` when replacing a live session) emits exactly one clean `OnDisconnect` (`WasClean=true`) for a live local teardown. Clearing the channel before `Close` prevents a duplicate transport `OnClose` notify; a second `Disconnect` with no active session remains a no-op.
- Interest-mode (and filtered broadcast) `ReplicationStats.StreamWireMsgs` always accumulates reliable-stream chunk counts for the completed pass, not only when `LogReplicationStats` logging is enabled, so public stats stay consistent with batched frame counts.
- Owner-only replication no longer risks leaking private bits from a former owner's eventual-state retry mask after ownership transfer: public eventual frames reapply `PublicReplicationMask` at serialize time, ownership full clear/grant clears that session/entity's eventual tracker, and loss/requeue preserves the public flag. Concurrent `Server.SetOwner` calls serialize Owner lookup, registry mutation, and refresh coalescing under `interestMu`.
- Generated `entities.proto` files now declare world collection fields with valid `repeated` or `map` protobuf types.
- Generated C# protobuf decoders now compile for maps and catalogs keyed by unsigned integers.
- Golem Scribe catalog export preserves previously committed type/world/data artifacts when a catalog class is temporarily invalid (errors are reported; bake is skipped only for that exporter); only truly removed or renamed catalog type names orphan-delete their managed files. Invalid catalog rows no longer reserve keys that would block a later valid asset with the same key.
- Golem Scribe auto-bake is decoupled per exporter: catalog collect/reconcile errors no longer suppress a required entity-schema bake, and entity errors no longer suppress a required valid catalog-schema bake.
- Golem Scribe YAML scalars now quote/escape newlines, carriage returns, tabs, and other C0 control characters.
- Golem Scribe now rejects absolute/`..` artifact paths, rolls back partial artifact mutations, keeps registry removals pending when registry updates fail, continues orphan cleanup when unrelated prefabs are invalid, and preserves external asset notifications while an export is running.
- Generated JavaScript `Client` types expose configured world managers directly, so typed world callbacks no longer require optional-manager checks or casts.
